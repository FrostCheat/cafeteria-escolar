07
Actualizaciones instantáneas

Tiempo real con
Server-Sent Events

SSE es una tecnología nativa del navegador que mantiene una conexión abierta. El servidor empuja datos sin que el cliente tenga que pedir.

Conexión
Cliente abre EventSource
El navegador hace GET a /api/sse?token=…. El servidor valida JWT y establece la conexión.
Estado inicial
Envío de datos al conectar
El servidor envía inmediatamente: turno actual, productos activos y pedidos del usuario (o todos si es admin).
Bucle de polling
Consulta la tabla events cada 5s
Detecta eventos nuevos por ID secuencial. Solo envía los datos que cambiaron. Heartbeat cada ciclo para mantener la conexión.
Reconexión
Auto-reconexión exponencial
El cliente espera 8s → 12s → 18s → hasta 60s entre intentos fallidos. Al reconectar, el delay se resetea.
Ciclo de vida
La sesión dura 40 segundos
Después de 40s el servidor envía evento reconnect y el cliente reconecta automáticamente.

Sistema de pagos

Dos formas de pagar,
una sola experiencia

El sistema soporta efectivo con QR y pagos digitales reales con PayPal SDK, incluyendo tarjeta, Apple Pay y Google Pay.

💵
Efectivo en cafetería
El estudiante confirma su pedido, recibe el QR al instante y paga en efectivo cuando retira. El encargado escanea el QR y marca como pagado.
Sin costos digitales QR inmediato Sin internet requerido
💳
PayPal · Tarjeta · Apple/Google Pay
El pago se captura del lado del servidor via API de PayPal. El pedido se crea como status: 'paid' automáticamente tras la captura.
Captura server-side Anti-duplicados Sandbox + Producción
🛡️
Protección anti-duplicados
Antes de capturar, verifica si el paypal_order_id ya existe en la base de datos. Si sí, devuelve error 409 sin crear un pedido doble.
⚙️
Flujo de captura
1. Frontend crea orden en PayPal → 2. Usuario aprueba → 3. Backend captura con token OAuth → 4. Verifica COMPLETED → 5. Crea pedido en BD.
📋
Webhook alternativo
Si el backend falla tras capturar, se muestra el paypal_order_id al usuario para que el admin lo registre manualmente. Ningún pago se pierde.
09
Capas de protección

Seguridad en
cada nivel

El sistema implementa múltiples capas de seguridad para que nadie acceda a lo que no le corresponde.

🔑
JWT — Tokens firmados
Algoritmo HS256 con hash_equals() contra timing attacks. Expiración en 7 días. Payload con rol, ID y email.
🔒
bcrypt para contraseñas
Las contraseñas nunca se guardan en texto plano. Hash irreversible con PASSWORD_BCRYPT. Ni el admin puede verlas.
🛡️
SQL Injection: imposible
100% Prepared Statements con PDO en todas las consultas. Los datos del usuario se tratan como texto, nunca como código SQL.
📧
Correos institucionales
Validación del dominio en registro y login. Solo acepta @santajuanalestonnac.edu.co. Personas externas no pueden registrarse.
🚦
Roles y permisos
Cada endpoint admin usa requireAdmin(). Un token de estudiante válido recibe 403 en rutas de admin, sin importar el contenido del JWT.
📝
Sistema de logs
Toda acción registrada con timestamp, IP, URI y nivel. Rotación automática al superar 5MB. Historial de hasta 5 archivos. Acceso bloqueado desde el exterior.
.htaccess
Bloquea acceso directo a .log .sql .env .json .ini. Deshabilita listado de directorios. Preserva el header Authorization que Apache a veces elimina.
QR Token de 48 caracteres hex
Generado con random_bytes(24) — criptográficamente seguro. Único por pedido. Imposible de predecir o falsificar.
